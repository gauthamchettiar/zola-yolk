{% import "macros/sections.html" as paths %} {# Series: several posts that are meant to be read in order. A post joins one by naming it under its own [extra], along with where it sits in the order: [extra] series = "Shortcodes" series_part = 2 # 0 marks the series' overview page Part 0 is the page that introduces the series rather than continuing it, so it sorts first, is numbered 0 in the list, and its `description` is what the listing page uses to explain what the series is about. A series has three views, and one macro renders all of them: label — one line saying which part of which series this is, which goes in a post's header, under its date nav — the previous/next links that go under a post index — every series on the site, each with its parts, for a listing page (see templates/series.html) They are one macro because they all need the same thing first: the pages of a series, in order. A Tera macro returns a string and nothing else, so that list cannot be gathered once and handed to a second macro — splitting the views up would mean gathering it two or three times, in as many places, which is how they would end up disagreeing about what a series contains. #} {# Renders one of the three views of a series. Nothing is rendered for a page that names no series, or for a series with only one page in it. view — label | nav | index (default: "label") page — the page object, for the views that are about a post: it supplies the series, the position in it, and which part to mark as current. `index` needs none of that and takes no page (default: false) name — the series to render, when it isn't `page`'s own. `index` ignores it and renders every series there is (default: "") text — label only: the line to render, with {part}, {count} and {series} filled in. {series} links to the series' overview page (series_part = 0) when it has one, and otherwise to the series' entry on the listing page named by config.extra.series_page, when that section exists (default: "Part {part} of {count} from series “{series}”") #} {% macro show(view="label", page=false, name="", text="Part {part} of {count} from series “{series}”") -%} {#- What the caller is: a post knows its own series and where it sits in it; a listing page knows neither, and renders every series instead. -#} {%- set_global _name = name -%} {%- set_global _current = "" -%} {%- set_global _part = -1 -%} {%- if page -%} {%- if not _name -%}{%- set_global _name = page.extra.series | default(value="") -%}{%- endif -%} {%- set_global _current = page.permalink -%} {%- set_global _part = page.extra.series_part | default(value=-1) -%} {%- endif -%} {#- Where to look for the pages of a series. config.extra.content_sections is the site's list of post sections; with none set, a post's series is assumed not to leave the section the post itself is in, and a listing page — which has no section to start from — falls back to every section at the root. Only a section's own pages are searched, not its subsections'. -#} {%- set_global _paths = [] -%} {%- if config.extra.content_sections -%} {#- A name whose section does not exist is skipped rather than aborting the build — see macros/sections.html. -#} {%- for section_name in config.extra.content_sections -%} {%- set _path = paths::resolve(name=section_name) | trim -%} {%- if _path -%} {%- set_global _paths = _paths | concat(with=_path) -%} {%- endif -%} {%- endfor -%} {%- elif page -%} {%- set_global _paths = [page.ancestors | last] -%} {%- else -%} {%- set root = get_section(path="_index.md") -%} {%- set_global _paths = root.subsections -%} {%- endif -%} {#- A series is a local grouping, so `list = "local"` is still part of one and only `never` is held back. See macros/list.html. -#} {%- set_global _pool = [] -%} {%- for path in _paths -%} {%- set sec = get_section(path=path) -%} {%- for candidate in sec.pages -%} {%- if candidate.extra.list | default(value=config.extra.list | default(value="always")) != "never" -%} {%- set_global _pool = _pool | concat(with=candidate) -%} {%- endif -%} {%- endfor -%} {%- endfor -%} {#- Which series to render: the one the post is in, or all of them, in name order.
